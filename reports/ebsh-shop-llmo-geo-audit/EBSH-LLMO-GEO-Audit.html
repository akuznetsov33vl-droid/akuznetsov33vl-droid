0. Резюме для руководителя (1 страница)

Вердикт

Общая оценка готовности к AI-поиску и шопингу: 28 / 100

Сайт сейчас почти не готов к корректному отображению и рекомендации товаров в ChatGPT Search, OpenAI Shopping, Perplexity, Google AI Overview, Gemini, Claude и Bing Copilot.

Причина не в «магии ChatGPT», а в базовых блокерах индексации и данных о товаре. Без их снятия вложения в контент и GEO дадут минимальный эффект.

Три факта, которые меняют решение об инвестиции

  1. Главная страница закрыта от индексации: <meta name="robots" content="noindex,nofollow">. Бренд и входная точка сайта для поисковиков и AI-краулеров фактически «невидимы».
  2. Во всех 26 карточках в Schema.org цена = 0, при этом availability = InStock. Для OpenAI Shopping / товарных сниппетов это дисквалифицирующий сигнал.
  3. Описания товаров для машин = «КУПИТЬ НА WILDBERRIES / OZON». Нет материала, цвета/размера в structured data, GTIN, Brand, отзывов. LLM не из чего цитировать карточку.

Клиент уже верно назвал часть проблем: «настроить цены, сделать разрешение индексации». Аудит подтверждает: это этап 0, не опция.

Стоит ли вкладываться?

Сценарий Рекомендация
Цель — продажи только на WB/Ozon/ЯМ Минимальный пакет на сайте (индексация + цены + базовый schema + llms.txt), основной GEO — карточки маркетплейсов. Бюджет ниже.
Цель — чтобы бренд EBSH и товары цитировались в ChatGPT Нужен полноценный GEO-контур на своём домене: карточки с данными, структура каталога, E-E-A-T, AI-файлы. Без этого ChatGPT будет опираться на маркетплейсы / чужие источники.
Цель — OpenAI Shopping (кнопка покупки / товарная выдача) Требуется модель «купить на сайте» или официальный merchant-feed партнёра. Сейчас checkout уведён на маркетплейсы и Telegram — Shopping на ebsh.shop маловероятен без смены commerce-модели.

Практичный вывод для заказчика: инвестировать имеет смысл поэтапно. Сначала дешёвые критические правки (8–16 ч) — они открывают индексацию. Затем данные товара и schema. Полноценный OpenAI Shopping — только если появится покупка на домене или feed.

Как внедрить (рекомендуемый путь на Tilda)

  1. HTML-блок в шаблон товара / через Tilda Zero / кастомный JS, генерирующий JSON-LD из полей Store.
  2. Либо вынести витрину на стек с полным контролем head (Shopify/Bitrix/самопис) — если GEO/Shopping станет KPI.
  3. Минимальный JSON-LD на товар:
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Футболка-поло зеленая",
  "image": ["https://.../image.webp"],
  "description": "Мужская футболка-поло EBSH, цвет зелёный, состав …, размерная сетка …",
  "sku": "EBSH-POLO-GRN",
  "gtin13": "460XXXXXXXXXX",
  "brand": { "@type": "Brand", "name": "EBSH" },
  "color": "зелёный",
  "material": "хлопок …",
  "size": "M",
  "audience": {
    "@type": "PeopleAudience",
    "suggestedGender": "male"
  },
  "offers": {
    "@type": "Offer",
    "url": "https://ebsh.shop/catalog/tproduct/...",
    "priceCurrency": "RUB",
    "price": "2490",
    "availability": "https://schema.org/InStock",
    "itemCondition": "https://schema.org/NewCondition"
  }
}

Для вариантов размеров — ProductGroup + hasVariant / variesBy (size, color).

Roadmap

Этап 1 — Разблокировка индексации (1–2 итерации)

  • Снять noindex с главной и /tproduct/ товаров.
  • Канонизировать www → apex (или наоборот).
  • Пересобрать sitemap: +home, −thanks, единый URL-паттерн товаров.
  • Проставить meta description и title с брендом.
  • Зафиксировать цены в карточке Store (не 0) и проверить выдачу в microdata.

Сложность 2/5 · 4–8 ч · Эффект: критический (без этого GEO бессмысленен).

Этап 2 — Данные товара и Schema

  • Уникальные описания 150–400 слов: состав, посадка, цвет, уход, размерная сетка.
  • Поля Brand, material, color, size; уникальные SKU; GTIN где возможно.
  • JSON-LD Product + Offer (+ ProductGroup для размеров).
  • Organization + WebSite на всех страницах; FAQPage на главной; BreadcrumbList.
  • Alt-тексты, og:image на всех PDP.

Сложность 3–4/5 · 20–40 ч · Эффект: высокий для ChatGPT/AI Overview цитирований.

Этап 3 — GEO и AI-навигация

  • Опубликовать /llms.txt (карта сайта для LLM по образцу ЦУМ/Love Republic).
  • Опционально /ai.txt с правилами цитирования и контактами.
  • Контент-хабы: размерная сетка, «как выбрать», материалы, lookbook.
  • Усилить бренд-дисambiguation: «EBSH — российский бренд мужской одежды (не спортхаб ЕБШ)».
  • Перелинковка категория → товар в HTML (не только JS).

Сложность 3/5 · 12–24 ч · Эффект: средний–высокий на цитируемость.

Этап 4 — Commerce / Shopping (опционально, стратегическое решение)

  • Если цель — OpenAI Shopping / Google Shopping: on-site checkout или merchant feed + актуальные остатки/цены.
  • Иначе зафиксировать стратегию «сайт = бренд + контент, продажи = MP» и оптимизировать карточки WB/Ozon параллельно (цены, индексация карточек MP, атрибуты).
  • Отзывы + AggregateRating на своём домене или трансляция рейтингов (с юридической корректностью).
  • Ускорение: урезание лишних Tilda JS, оптимизация LCP hero.

Сложность 4–5/5 · 40–80+ ч · Эффект: высокий только при смене/дополнении commerce-модели.

Финальный вывод

Чтобы товары EBSH максимально корректно отображались и рекомендовались в ChatGPT, OpenAI Shopping и других AI-системах, нужно:

  1. Снять технические запреты индексации (главная и товары) и склеить зеркала www.
  2. Сделать машиночитаемые правдивые данные товара: цена ≠ 0, наличие, SKU/GTIN, бренд, цвет, размер, материал, нормальное описание и изображения с alt.
  3. Отдать эти данные в JSON-LD (Product/Offer + Organization/WebSite/FAQ/Breadcrumb).
  4. Дать LLM карту сайта (llms.txt) и цитируемый экспертный контент (размеры, материалы, бренд).
  5. Честно выбрать commerce-модель:
  6. витрина + MP → цель = цитирование бренда/товаров (Shopping на домене не приоритет);
  7. продажа с сайта / feed → отдельный проект под OpenAI Shopping / Google Merchant.

Пока пункты 1–2 не закрыты, расходы на «оптимизацию под ChatGPT» не окупятся: модели не увидят или не смогут доверять каталогу.

Приложение A. Метод аудита

  • HTTP/HTML съеём: главная, catalog, about, contacts, oplata, thanks, 26 URL из sitemap-store.xml.
  • Проверка robots/llms/ai/manifest, заголовков, canonical, meta robots.
  • Разбор microdata Product/Offer.
  • Замеры TTFB/размеров.
  • Сравнение с публичными сигналами конкурентов (в т.ч. llms.txt ЦУМ, Love Republic).
  • PageSpeed API: квота исчерпана на момент прогона — CWV оценены косвенно.

Ограничения внешнего аудита: нет GSC/Яндекс.Вебмастер, нет админки Tilda, нет выгрузок остатков MP. Для «платного углублённого» этапа нужна админка Tilda + доступы вебмастеров.

Приложение B. Быстрый чеклист для исполнителя в Tilda

  1. Главная → настройки страницы → разрешить индексацию.
  2. Товары «Ради мечты» → убрать noindex или 301 на /catalog/tproduct/....
  3. Store → у каждого товара цена, описание, характеристики.
  4. Сайт → домен → редирект www.
  5. Sitemap: переиздать, убрать thanks, добавить home.
  6. HTML-блок JSON-LD + файл /llms.txt через Tilda «файл» / прокси.
